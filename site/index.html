Hardening my homelab: 9 findings to 0

Vulnerability managementTested Oct 20, 2026
9 → 0real findings

Greenbone found 6 Medium and 3 Low issues on my Ubuntu server. I fixed or contained each real one, rescanned with the same settings, and proved the last Medium was a false positive.

Tools: Greenbone/OpenVAS · OpenSSH · ufw · nginx (TLS reverse proxy) · Docker · Tailscale · sysctl

Case study: problem, actions, evidence, lessons
Problem
A baseline scan (Full and fast, all TCP ports plus the top 100 UDP ports, QoD ≥ 70) found a cleartext panel login over HTTP, weak crypto on the vendor's SFTP ports, weak SSH MACs, and TCP/ICMP timestamp leaks.
Actions
  • Restricted SSH to strong MACs, key exchange and ciphers. Validated with sshd -t and reloaded without dropping my session.
  • Put a hardened TLS reverse proxy in front of the panel and dropped plain HTTP.
  • The vendor's SFTP crypto can't be changed, so I limited those ports to Tailscale with ufw before.rules.
  • Disabled TCP timestamps and dropped ICMP timestamp requests.
Evidence
Before and after Greenbone reports with the same scan config: baseline Oct 20, 2026, 2:37 AM ET; rescan 7:48 PM ET the same day. Sanitized configs are in the GitHub repo.
Result
Medium/Low went from 9 to 1, and that 1 is a documented false positive (the app returns HTTP 200 for every path). 0 Critical/High before and after.
Residual risk
The weak SFTP algorithms still exist, but only authenticated Tailscale devices can reach them.
Lessons
If you can't fix something, contain it and write down the residual risk. Confirm every fix with a rescan or a direct test.

Building a home SOC with Wazuh

Detection & SIEMTested Oct 20, 2026
5710 → 5712brute-force correlation

I deployed a single-node Wazuh 4.14.9 SIEM, attacked my own isolated lab, and recorded what it detected. That includes a SQL injection it missed.

Tools: Wazuh (SIEM, FIM, CIS benchmark) · Docker · DVWA · OWASP Juice Shop · nginx · MITRE ATT&CK

Case study: problem, actions, evidence, lessons
Problem
I wanted to see attacks from the defender's side and test whether my detections actually fire.
Actions
  • Enrolled my server as an endpoint: auth logs, ufw logs, Docker events, real-time file integrity monitoring on /etc, and the CIS Ubuntu 24.04 benchmark.
  • Ran DVWA and Juice Shop on a Docker internal network with no internet egress. The lab is off unless I start it.
  • Replaced every default password before first boot and kept the indexer and API on localhost only.
Evidence
6 failed SSH logins produced 11 rule 5710 alerts and 1 level-10 rule 5712 brute-force correlation (MITRE T1110). The FIM test fired rules 554/550/553. A UNION SQL injection fired rule 31106.
Detection gap
A boolean ' OR '1'='1 SQL injection succeeded and raised no alert. Next step: a custom Wazuh rule, or ModSecurity with the OWASP Core Rule Set.
Triage
My own Greenbone rescan set off 735 rule 5710 alerts. I traced them to the scanner's container and confirmed it was authorized activity.
Lessons
Test your detections, because signatures have gaps. One correlated alert is more useful than hundreds of raw ones.

Hardened self-hosting with a Cloudflare Tunnel

Secure hostingChecked Oct 20, 2026
0 of 1,007IPv4 TCP ports open

This site runs on my homelab server in a locked-down nginx container. The server connects out to Cloudflare, so my router has no port forward for the site.

Tools: Docker · nginx-unprivileged · Cloudflare Tunnel · Content Security Policy · ufw

Case study: problem, actions, evidence, lessons
Problem
I wanted to host a public website from home without opening an inbound port on my router.
Actions
  • nginx runs as a non-root user with a read-only filesystem, cap_drop: ALL, no-new-privileges and resource limits.
  • The container listens only on localhost, and cloudflared connects out to Cloudflare.
  • A strict CSP (default-src 'none', no inline scripts) plus nosniff, frame and referrer headers.
Evidence
An outside-in check with public checkers, each validated against a host with known open ports: 0 of 1,007 IPv4 TCP ports open. On IPv6, 16 common ports on each of 2 addresses all timed out.
Limits
Not a full 65,535-port TCP scan, and UDP wasn't tested. The check ran on Oct 20, 2026, before the site went live. The tunnel only makes outbound connections.
Lessons
The safest open port is no open port. State the scope of every security claim.
